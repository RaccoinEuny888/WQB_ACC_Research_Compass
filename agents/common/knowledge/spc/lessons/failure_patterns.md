# SPC Prompt 常見失敗樣式

> 從多份 prompt 的測試過程歸納出來的**操作化失敗樣式**：問題出在「把假說寫成 prompt」這一步，
> 不在假說本身。內容已抽象化，不含具體假說、標的或成績。
>
> 證據等級：`R`＝規則或官方說法；`H`＝推測，未驗證；`O1`＝單一 prompt 觀察到；
> `O2`＝≥ 2 份獨立 prompt 重現。O1 只能當「要注意的可能性」，不是通則。

## 總表

| # | 樣式 | 症狀 | 處方 | 等級 |
|---|---|---|---|---|
| 1 | 裸 ISIN 吃光搜尋額度 | 覆蓋率低、方向亂跳；分析步驟根本沒執行 | universe 改 `TICKER = ISIN\|MIC` 對照格式 | O1（根因由一份稽核確認；其他份是推測同因，H） |
| 2 | 「無訊號可省略」導致覆蓋崩 | 輸出只有少數檔，跨輪重疊率低 | 全名單都要給分，無訊號給最小絕對值（如 ±0.005~0.010） | O1 |
| 3 | 機制天生證據稀疏 | 合格案例太少，填不滿清單，覆蓋率長期偏低 | 換 universe 切法（先篩出「有事件」的標的），或接受低覆蓋設計，或改走量化回測通道 | O2 |
| 4 | 軟性聚合判斷不穩定 | 格式完美、覆蓋完美，但跨輪正負號大量翻轉 | 判準錨定在單一權威、格式固定的數據源；不要讓模型自己聚合多來源下結論 | O2 |
| 5 | 機械規則方向仍不一致 | 方向本該由公式決定，卻跨輪亂跳；甚至改寫 prompt 給定的字串 | 視為「模型沒查」，修查找流程；一致率 < 90% 不必再討論假說 | O1 |
| 6 | 多空兩側強度不對稱 | 一側穩定、另一側差異化永遠不過 | 承認實際有效的那一側，重新定位 prompt 的主方向 | O1 |
| 7 | 清單內含無效 ISIN | 模型自報查無此碼、給中性分 | 生成時驗算 Luhn 檢查碼＋全量反查 | O1 |
| 8 | 依單日 PnL 調權重 | 權重頻繁變動、事後撤回 | 不依單日表現調權重 | R（官方 tip） |
| 9 | 產物落檔但索引沒更新 | 下個 session 以為沒做過，重做一輪 | 產出檔案的同一輪就更新登記簿與索引 | O1 |

## 詳述

### 1. 裸 ISIN 吃光搜尋額度
- **怎麼發生**：universe 只貼 `ISIN|MIC`，模型每輪都得先把幾十個 ISIN 反查成公司，才能開始分析。搜尋額度花在辨識身分上，後面的分析步驟沒做，最後憑印象給分。
- **怎麼看出來**：要求模型附上「查到的關鍵數值」，會發現很多檔沒有數值或數值明顯過時。
- **處方**：清單寫成 `AAPL = US0378331005|XNAS`，輸出 key 仍用 `ISIN|MIC`。

### 2. 「無訊號可省略」導致覆蓋崩
- **怎麼發生**：prompt 寫「沒有明確訊號的標的可以省略」。在公開資訊稀疏的訊號上，模型會大量省略，覆蓋遠低於目標，每輪省略的又不同，重疊率也跟著崩。
- **處方**：全名單都要給分；無訊號的給固定小絕對值，方向依假說的預設側。

### 4. 軟性聚合判斷不穩定（最隱蔽的一種）
- **怎麼發生**：判準是「模型自己綜合多篇新聞判斷市場反應方向」這類沒有標準答案的任務。即使同一時段連跑、真實資訊沒變，換個搜尋角度就讀出不同結論。
- **為什麼隱蔽**：格式、覆蓋、差異化全部完美通過，只有跨輪方向檢查會抓到。連模型自己點名的「最強訊號」都可能翻轉。
- **已排除的解法**：換更強的模型、把判準寫成公式，都救不了「輸入本身有噪音」。
- **處方**：方向判準錨定在單一權威、格式固定的數據（例如官方公告的數字、可直接查到的價格／均線）。模型只決定幅度，不決定方向。

### 5. 機械規則方向仍不一致
- **怎麼發生**：方向設計成機械規則（例如收盤價高於均線＝正），理論上應接近 100% 一致，實測卻大量翻轉；同一輪還出現把 prompt 給定的 MIC 改寫成別的值。
- **判讀**：三條證據一起指向「模型沒有執行查找」，而不是假說錯。這和 #1 常常同時出現。
- **處方**：先修查找（#1、測試期稽核欄），再談假說。

### 6. 多空兩側強度不對稱
- **怎麼發生**：原本設計成「錯殺後做多」，實測卻發現做多側幾乎找不到乾淨案例，差異化永遠不過；反而是「識破假訊號、抓真利空」的做空側很穩定。
- **處方**：不要硬救失敗的那一側。依實際有效的方向重新定位，或拆成兩份 prompt。
