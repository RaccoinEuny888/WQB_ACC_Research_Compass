# SPC 提交格式規範（FORMAT SPEC）

> 把官方規則（`../rules/SPC_official_guideline.md`）與平台表單（`../rules/submission_form_fields.md`）
> 轉成逐欄判準與驗證清單。
> **提交不可逆**：提交後不能改內文、不能刪除，只能把權重歸零。所以本清單要全部通過才提交。

## 一、提交表單逐欄規範

| 欄位 | 規範 | 判準／慣例 |
|---|---|---|
| **Prompt Name** | `<機制縮寫>-<universe縮寫><檔數>-v<版>`，如 `MechanismX-USMid25-v1` | 跟自己的登記簿、假說卡對得上。因為內文不能改，修改＝提交 v2，再把 v1 權重歸零 |
| **Model** | 從平台提供的選項中選 | 需要深度 web search 推理的假說選推理最強的模型；每日更新的簡單篩選可選快速模型 |
| **Model Version** | 照平台當時的選項填 | 記進登記簿：同一個 prompt 換模型，表現差異是可比較的實驗變因 |
| **Update Frequency** | Daily / Weekly / Monthly / Quarterly | **跟著訊號半衰期走**：事件型（財報窗、評等變動）＝Daily／Weekly；基本面重估型＝Weekly／Monthly；結構型＝Monthly／Quarterly。更新比訊號變化慢會漏訊號，比訊號快只會多引入噪音 |
| **Prompt Weight** | 0~1，最多兩位小數 | 首次提交建議 **0.05~0.10**（低權重觀察期）；持續 fail 就歸零（見 `FEEDBACK_PROTOCOL.md`） |
| **Prompt 本文** | **≤ 10,000 字元（硬上限）** | 字元預算見第二節 |
| **Sample Prompt Output** | 貼實測輸出 | 必須是第 3 次實測的真實輸出，不可手寫示意 |

## 二、Prompt 本文字元預算（10,000 上限的分配）

| 區塊 | 建議字元 | 內容 |
|---|---|---|
| 專家角色＋任務 | ~600 | persona、目標、輸出物一句話 |
| 分析工作流（四柱轉步驟） | ~1,800 | 逐步驟：每步看什麼證據、量化判準 |
| 強制 web search 指令 | ~300 | 搜什麼、用什麼來源、禁止用記憶中的數字 |
| Bull／Bear Gate | ~400 | 兩面論證要求 |
| Universe 清單 | ~1,100 | 建議用 `TICKER = ISIN\|MIC` 對照格式（理由見 `../lessons/failure_patterns.md` #1） |
| 信心分數規則＋格式鎖定尾註 | ~500 | 見第三節 |
| **緩衝** | ~5,300 | 不要用滿，留給修訂版（v2 也受同一上限） |

超限時的刪減順序：先砍工作流的冗詞 → 再縮 universe → **絕不砍格式鎖定尾註與 web search 指令**。

## 三、輸出合約（JSON）

```json
{
  "US0378331005|XNAS": 0.085,
  "US0231351067|XNAS": -0.040
}
```

1. **Key**：`ISIN|MIC`，必須來自該 prompt 附的 universe 清單。清單外的 key＝幻覺，該次輸出作廢
2. **Value**：數字，小數 **3 位**；正＝做多、負＝做空、絕對值＝信念強度
3. **強制差異化**：不得等權。判準：同號分數中，最大絕對值 ≥ 2 × 最小絕對值，且至少有 3 個不同的值
4. **建議值域**：±0.010 ~ ±0.100（與官方範例同量級）；0＝無信念
5. **多空結構自由**（SPC 無中性限制）：可全多、全空或混合，但方向分布要和假說一致（做空型假說卻輸出全正分＝邏輯錯誤）
6. **純 JSON**：無 markdown 圍欄、無前後文字、無註解、無尾逗號
7. 格式鎖定尾註（一字不差放在 prompt 結尾）：
   > Output ONLY the raw JSON object. Do not include any conversational filler, markdown formatting (like ```json), or explanatory prose.

## 四、提交前驗證清單（逐項打勾，全過才提交）

**格式驗證（每次輸出都要做）**：
- [ ] 輸出能被 JSON parser 直接解析（實際 parse，不用目測）
- [ ] 所有 key 符合 `^[A-Z]{2}[A-Z0-9]{9}[0-9]\|(XNYS|XNAS)$`（美股；ISIN 不限 US 開頭，海外註冊但直接掛牌的普通股用當地國別碼），且都在 universe 清單內
- [ ] 所有 value 是 3 位小數的數字，落在建議值域
- [ ] 差異化判準通過（非等權）
- [ ] 覆蓋檔數＝目標 ±20%

**穩定性驗證（乾淨的 chat 視窗跑 3 次，最好同一時段連續跑完）**：
- [ ] 3 次全部通過格式驗證
- [ ] 3 次的標的重疊率 ≥ 70%（名單大幅漂移＝判準不夠明確，回去收緊工作流）
- [ ] 同一檔標的 3 次方向一致（分數大小可變，正負號翻轉＝不穩定）
- [ ] **若方向由機械規則決定**（例如價格在均線上／下），方向一致率 < 90% 即判定「模型沒有真的執行查找」，先修查找流程，不必再討論假說對錯
- [ ] 輸出反映近期事實：抽 2 檔核對分析引用的是近期 filings／news，而不是預訓練舊資料

**一致性驗證**：
- [ ] 方向分布和假說卡的多空邏輯一致
- [ ] Prompt Name、登記簿、假說卡三處互相對得上

**表單驗證**：
- [ ] 本文 ≤ 10,000 字元（實際數，不目測）
- [ ] Update Frequency 與訊號半衰期匹配
- [ ] 首次權重在 0.05~0.10
- [ ] Sample Output 是第 3 次實測的真實輸出

## 五、測試期專用的稽核欄（定案前拿掉）

測試時可以要求模型在 JSON 之外，另附一段「每檔查到的關鍵數值＋來源」。
這樣能稽核它有沒有真的查，而不是憑印象給分。定案提交前再移除這段要求，恢復純 JSON 輸出。
